# v0.2.0 release-hardening — CLI ↔ docs drift matrix

Part B "start here" deliverable for `rfc-v0.2.0-release-hardening`. Audits
the four top-level docs (`README.md`, `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`)
against the **actual** CLI surface, derived from `corpus_forge/cli.py` (and
its mounted sub-`typer.Typer()` apps) plus `corpus-forge <cmd> --help` run via
`uv run` in the `doc-drift` worktree. Code is the source of truth.

Audited at: branch `nightly/v020-doc-drift-matrix`, based on `origin/main`.
Scope: the four top-level docs only (not the wider `docs/` tree).

## Authoritative CLI surface (ground truth)

Top-level commands: `ingest`, `embed`, `daemon` (DEPRECATED → `service start`),
`version`, `setup`, `update`, `doctor`, `bug-report`, `search`, `classify`,
`rechunk`, `enrich`, `estimate`, `prune`, `capabilities`, `migrate`, `logs`,
`config`, `embedder`, `ollama`, `dataset`, `source`, `service`, `ignore`,
`bench`, `models`, `hosts`, `export`, `sync`, `eval`, `agents`, `analyze`,
`feedback`, `mcp`, `chunk`.

Key sub-apps:
- `setup` flags: `--non-interactive`, `--quick` (`CF_QUICK`), `--config-dir`,
  `--embed-lanes`, `--join` (`CF_JOIN_DSN`). **No `--backend` / `--embedder`
  flags** — those answers come from `CF_BACKEND` / `CF_EMBEDDER` env vars in
  non-interactive mode (see `corpus_forge/setup/questions.toml`).
- `mcp serve`: `--transport` (only `stdio`), `--dataset`/`-d`, `--writes`/`--no-writes`.
- `embed`: `-e` (required), `-d`, `-l`, `--image`.
- `search`: `--k`, `--dataset`/`-d`, `--fusion`, `--alpha`, `--rerank`, `--json`.
- `embedder`: `list get add remove set-active test repair-indexes gc`.
- `service`: `status start stop restart logs install uninstall`.
- `config`: `path get set unset show validate edit publish pull diff`.
- `export`: `chat sdft feedback-pairs`.
- `eval`: `retrieval corpus-quality rag cag distill embedders`.
- `migrate`: bare invocation runs the upgrade (callback `invoke_without_command`);
  subcommands `revision`, `history`.
- Embedder `provider` enum (config.py:398/431): `sentence_transformers | openai |
  model2vec | llama-cpp`.
- Config-path env var honored by `Config.load()` (config.py:1745): `CORPUS_FORGE_CONFIG`.

## Summary

- **Total drifts found: 3 STALE + 1 latent-code-inconsistency flagged + 2 OK-ambiguous-left + 1 internal-help count noted.**
- **STALE-FIXED: 3** — CLAUDE.md setup flags, README coverage floor, README provider enum.
- **MISSING-FEATURE / latent-code-inconsistency FLAGGED (not fixed): 1** —
  `CF_CONFIG` vs `CORPUS_FORGE_CONFIG`: service units bake `CF_CONFIG` but the
  loader only reads `CORPUS_FORGE_CONFIG`. Needs a **code** decision (make
  `Config.load()` accept `CF_CONFIG` as a fallback, or switch the units to
  `CORPUS_FORGE_CONFIG`), not a doc edit. Docs left untouched.
- **OK-ambiguous (left): 2** — README's `CORPUS_FORGE_CONFIG` MCP block (it is
  the *correct* one given current code), and the deprecated-but-working
  `daemon` in the NSSM Windows example.
- **Out-of-scope note:** the `--writes` help string ("16") and a server docstring
  ("8") both undercount the 17 registered write tools — a code/help cleanup, not
  in the four audited docs.

The four top-level docs are in **good shape** overall — the CLI surface is large
and the docs track it closely. The only genuinely stale, unambiguous tokens were
the three fixed above; everything else is either correct or a code-side
inconsistency that doc edits shouldn't paper over.
