# Phase O — Exploratory Data Analysis + Corpus Cleaning

**Motivation:** corpus-forge today is strong on storage / retrieval / curation but has no ML/NLP layer that turns the corpus from "indexed bytes" into "trainable, ranked, curated training material." Phase O ships EDA + cleaning primitives (token stats, exact / near-dup, language detection, drift, topics), persists a per-chunk learned-quality signal, and plugs that signal into the curation selector behind a presence flag (the table being empty = no behavior change).

**Source plan:** `/Users/evanowen/.claude/plans/let-s-add-look-at-imperative-patterson.md` § Phase O. Phases P and Q are downstream context only.

**Target release:** `0.1.0b7`.

**Status:** planning → execution. Workflow: tdd-principal owns this doc; orchestrator (parent session) commits per wave on workers' behalf — 1Password SSH signing needs a TTY which subagents don't have.

## Decisions locked with the user

- One phase document, four waves (O1 → O4).
- Each wave: RED → GREEN → wave gate. Orchestrator stages + commits per `feedback_tdd_worker_commits.md`.
- **Migration follows project convention: forward-only with no-op `downgrade()`** (mirrors `0008`, `0010`, `0011`). The plan's "Clean downgrade" wording is a deviation we override — the integration test asserts `upgrade` provisions the schema and `downgrade` is a no-op (per `0010_document_label_confidence.py:36–40` precedent).
- **Test file naming**: existing `tests/unit/` is flat (no `tests/unit/cli/` etc. — those are top-level `tests/cli/`). Plan calls for `tests/unit/analyze/test_*.py`. We use **flat naming** to match the surrounding `test_config_*`, `test_retrieval_*`, `test_curation_*` precedent: e.g. `tests/unit/test_analyze_config.py`, `tests/unit/test_analyze_stats.py`. Integration tests live flat under `tests/integration/`: `tests/integration/test_migrate_0012_analyze.py` (matches `test_migrate_image_embeddings.py` precedent at `tests/integration/test_migrate_image_embeddings.py`).
- **Curation selector regression gate (O3)**: the table-empty path must produce **byte-identical** ordering, score, AND `ScoreBreakdown` output vs. a pinned baseline pickle (`tests/fixtures/curation/selector_baseline.pickle`). `ScoreBreakdown.learned_quality` is `None` (not `0.0`) when no learned signal row exists — so the dataclass shape changes but byte-equality is preserved only on the *behavior-observable* fields (ordering + score). The pickle baseline is regenerated by the tester on RED-day from current main and committed alongside the test.
- **Model integrations are local-or-remote via config** (project memory `project_model_local_or_remote.md`). `AnalyzeConfig.judge_endpoint` + `judge_model` mirror the proven `ClassifierConfig.llm_url` / `llm_model` pattern (`corpus_forge/config.py:488–492`). Both local (Ollama `http://localhost:11434`) and remote (OpenAI-compat) examples ship in `config.example.toml`.
- **Heavy ML deps lazy-load on first call** (project memory `project_phase_d_treesitter_lazy_fetch.md`). BERTopic / UMAP / HDBSCAN / fasttext / sklearn / datasketch all imported INSIDE function bodies, not at module top. Wave gate CI guard: `time corpus-forge --help` not slower than current baseline + 100ms.
- **`corpus-forge` does preprocessing only** (`project_corpus_forge_scope_no_training.md`). Phase O's learned-quality model is sklearn-over-existing-signals — fine, that's classification not generation. Phase O ships no LLM-as-judge surface; that lives in Phase P (`eval rag`).

## Wave O2 — De-dup, language detection, drift

### Goal

Ship the three "make-the-corpus-inspectable" primitives: exact-dup grouping (GROUP BY `chunks.content_hash`), near-dup clustering (MinHash LSH via `datasketch`), language detection with dispatch through `AnalyzeConfig.language_detector`, and a distribution-drift comparator (`scipy.stats.ks_2samp` + JS divergence over token-length distributions + embedding-centroid cosine distance). Persist near-dup clusters to the `near_duplicate_clusters` table from O1.

### Red

- `tests/unit/test_analyze_dedup.py` (new):
  - `exact_duplicates(chunks)` → groups by `content_hash`; returns `{hash: [chunk_id, ...]}` for hashes with `len(group) > 1`. Singletons omitted.
  - `near_duplicates(chunks, threshold=0.85)` → returns `list[Cluster]` where `Cluster = dataclass(cluster_id: str, chunk_ids: list[int], similarity: float, method: Literal["minhash_lsh"])`. `cluster_id` is a stable hash over sorted `chunk_ids` so reruns yield identical IDs.
  - Hypothesis property: `near_duplicates(chunks=[c, c, c], threshold=0.5)` always clusters all three (identical text).
  - Hypothesis property: `near_duplicates(chunks_disjoint, threshold=0.85)` returns empty list (no cluster).
  - **Lazy-import smoke**: `import corpus_forge.analyze.dedup` does NOT import `datasketch` (use `sys.modules` snapshot).
- `tests/unit/test_analyze_language.py` (new):
  - With `AnalyzeConfig.language_detector="langdetect"`, `detect_language("The quick brown fox")` returns `{"language": "en", "confidence": float ∈ [0, 1]}`.
  - With `AnalyzeConfig.language_detector="fasttext"`, dispatches into the fasttext path (mock import; assert call shape, do NOT trigger a 120MB model download in unit tests — use a tiny fixture or a mock).
  - Lazy-import smoke: importing the module brings neither `fasttext` nor `langdetect` into `sys.modules`.
  - When `language_detector="langdetect"`, the fasttext module is NOT imported at any point during a full unit-test run that exercises only the langdetect path.
- `tests/unit/test_analyze_drift.py` (new):
  - `compare_distributions(chunks_a, chunks_b)` returns `{"ks_statistic": float, "ks_pvalue": float, "js_divergence": float, "centroid_cosine_distance": float | None}`. Centroid is `None` when neither side has embeddings.
  - Empty `chunks_a` or empty `chunks_b` returns a result with finite values where computable, `None` where not (no exception).
  - Identical distributions → `ks_statistic ≈ 0.0`, `js_divergence ≈ 0.0`.
- `tests/integration/test_dedup_persist.py` (new):
  - Both Postgres (docker) and SQLite classes.
  - `persist_clusters(session, clusters, method="minhash_lsh")` writes one row per `(cluster_id, chunk_id)` pair into `near_duplicate_clusters` with the cluster's `similarity` echoed on every row.
  - Re-running with the same clusters is idempotent: same row count, no duplicate rows (assert via `(cluster_id, chunk_id)` index check).
  - `computed_at` is populated.

### Risk / open question

- **MinHash LSH band/row tuning** — `datasketch.MinHashLSH(threshold=0.85, num_perm=128)` is the default starting point. If the perf gate fails at 5k chunks, the coder may tune `num_perm` down to 64 — document the trade-off (lower num_perm = faster + higher false-positive rate).
